# ink.js（日本語）

[English](ink.md)

音のエネルギーを「インクの滴下指示」に変換するモジュール（`AV.ink`）。
描画そのものは行わず、毎フレーム「どこに・どれだけの大きさ/濃さ/湿り気で落とすか」のキューを作り、`renderer.js` に渡します。

## 2つの入力経路

| 経路 | 使われる場面 | 検出の単位 |
|---|---|---|
| 帯域（`update`） | マイク、読み込んだファイル、ステムがない内蔵音声 | 混合音の低・中・高の3帯域 |
| ステム（`updateStems`） | ステムを用意した内蔵音声 | 楽器ごと（drums / bass / vocals / guitar / piano / other） |

### 分離モードのステムの出どころ
- **ローカルサーバーで自動分離**（`js/separator.js` + `tools/server.py`）: 読み込んだファイル（音源読込・ドロップ）は、分離モードのとき自分のPC上のサーバーへ送られ、Demucs（`htdemucs_6s`、6楽器）で分離されます。音声は外部に出ません。再生は待たせず、最初は帯域方式で動き、分離が終わった時点から楽器ごとの解析に切り替わります。結果は `.stems-cache/` に内容ごとに保存され、同じ曲は2回目から即座に使えます。
  - 起動: `start.bat` をダブルクリック（`.venv` の Python で `tools/server.py` を起動し、`http://127.0.0.1:8765/` を開きます。アプリ自体もこのサーバーが配信します）。
  - 環境（構築済み）: `.venv` に Python 3.13、torch 2.6.0 (CUDA 12.4)、demucs 4.1.0。作り直す場合は `python -m venv .venv` → `.venv\Scripts\python -m pip install torch==2.6.0 torchaudio==2.6.0 --index-url https://download.pytorch.org/whl/cu124` → `.venv\Scripts\python -m pip install demucs numpy`。
  - サーバーが動いていないと、分離モードは「ローカルサーバーに接続できません」と表示して通常モードで続行します。
  - 接続先は `config.js` の `AV.SEPARATOR_API`。別のホストで公開したページから使う場合は `--origin https://公開URL` を付けて起動します。
- **事前分離**: 内蔵音声など、制作側で用意したステム（下記）があればそれを使います。見つからなければ、ブラウザ内で分離します。

### ステム方式の事前分離（内蔵音声向け）
曲を事前に楽器ごとに分離し、サイトと一緒に配置します。再生は元の音声（`src`）で行い、ステムは**無音の解析専用**として同期再生します。各楽器が自分のステムの上でアタックを検出するため、ピアノのストラムなどが他の楽器に埋もれません。

1. 分離（曲ごとに1回）: `pip install demucs` のあと
   `python tools/separate.py "曲.mp3" --id mysong`
   → `stems/mysong/` に6本のmp3が出力されます（Demucs `htdemucs_6s`、128kbps）。
2. `js/config.js` の `AV.BUILTIN_AUDIO.stems` の `dir` を `stems/mysong/` にします。
3. `stems/` フォルダをサイトと一緒にデプロイします（公開リポジトリに置く場合は、音源の権利に注意し、`.gitignore` の `stems/` と `*.mp3` を調整してください）。

画面下部の「通常 / 分離」で解析モードを切り替えます（再生中も可）。
- 通常: 常に帯域方式。
- 分離: 内蔵音声ではステム方式。マイクや読み込んだファイルでは、帯域方式のままです。
ステムが見つからない・読み込めない場合は、分離モードでも自動で帯域方式に戻ります。
楽器ごとのインクの性格（大きさ・濃さ・高さの範囲・ピッチ連動の有無）は `config.js` の `AV.STEM_CFG` で調整します。

## 入力（帯域方式）
`AV.state`（`audio.js` が更新）から以下を読みます。

| 項目 | 内容 |
|---|---|
| `energy.bass / mid / high` | 帯域ごとの音量（0〜） |
| `flux.bass / mid / high` | 帯域ごとのスペクトルフラックス（音の立ち上がりの強さ） |
| `time` | 経過秒 |

帯域ごとの挙動は `config.js` の `AV.BAND_CFG` で調整します。

## 処理の流れ（`update()` を毎フレーム呼ぶ）

1. **アタック検出 `detectAttack`**
   各帯域のフラックスを自身の移動平均の1.3倍と比較し、急に伸びた帯域を検出。アタック時は移動平均がほとんど上がらないため、ストラムのような連続した音も拾えます。最も強い帯域だけが発火するため、ピアノの1音で基音と倍音がそれぞれ滴を落とすことはありません。`AV.ATTACK_GAP`（0.03秒）より短い間隔では発火しません。
2. **滴下 `spawn`**
   アタックごとに1滴。強さに応じて半径・顔料量が変わります。短い音は少量で乾きやすい（湿り気が低い）滴になり、ほとんど広がりません。
3. **持続供給 `updateFeeder`**
   音が保持されている間（エネルギーが発音時ピークの約78%以上）、同じ位置に弱い滴を毎フレーム追加します（最大9秒）。
   - 保持時間とともに半径が最大約6.5倍まで拡大
   - 供給するのは「色のついた水」：顔料は保持時間とともに指数的に減り、水（湿り気）だけが供給され続ける
   - シェーダー側でも、その場の顔料が約0.2に達したら供給分の顔料を止める（上限）
   → 長音は濃い芯にならず、**広く淡い滲み**になります。
4. **フォールバック `fallback`**
   アタックが明確でなくても音が大きい状態が続けば、一定間隔で滴を落とします。
5. **位置選択 `pickPosition`**
   ランダムに8候補を出し、直近8秒以内の滴から遠いものを選びます。同じ場所に偏らず、端にも寄りすぎません。ゴニオメーターの周囲は避けます。
   アタック時は音の高さ（`AV.state.pitchX`：直前フレームから最も伸びた周波数ビンを、約80Hz〜5kHzの対数軸で0〜1に変換）を横位置に対応させ、縦位置だけをランダムにします。低い音は左、高い音は右に落ち、ストラムは左右に流れる滲みになります。

## 公開API

| 関数 | 用途 |
|---|---|
| `update(canvasAspect)` | 再生中、毎フレーム呼ぶ |
| `idle()` | 停止中、毎フレーム呼ぶ（保持状態の解除） |
| `dropRandom(radius, pigment, wetness)` | ランダム位置に1滴（再生開始時など） |
| `take()` | 溜まった滴を取り出してキューを空にする |
| `reset()` | キューと保持状態を破棄（白紙に戻す時） |

## 滴のデータ
`{ x, y, radius, pigment, wetness, seed, kind }`
- `kind`: 0 = 単発の滴 / 1 = 持続供給
- `seed`: 滴ごとの形状乱数（同じ形が二度出ない）
- キュー上限は `AV.MAX_DROPS`（6）。シェーダー側の `u_drops[6]` と一致させる必要があります。超過時は持続供給を優先して捨て、なければ最古を捨てます。

## 調整のヒント
- 長音をさらに広く/淡く: `updateFeeder` 内の `grow`（係数 1.1、上限 5秒）と `thin`（下限 0.07）
- 反応の鋭さ: `config.js` の各帯域 `fluxMin`（小さいほど敏感）
- 滴の大きさ・濃さ: 各帯域の `r0` / `p0`
